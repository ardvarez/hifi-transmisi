✓ Prioritas Tinggi Otomasi (High ROI)

  • One-Time Feature: Event musiman atau modul sekali pakai yang tidak ada siklus rilis berikutnya.
  • Usability & Visual Polish: Pengecekan estetika, kenyamanan tata letak, dan flow intuitif manusiawi.
Prinsip: Otomasi ditujukan untuk efisiensi regresi, bukan mengotomasi semua hal. Slide 02

Apakah Automation Menggantikan Manual Testing?
03
💡

Jawaban Tegas: TIDAK. Keduanya adalah mitra komplementer — automation menguji yang diketahui (checking), manual mengeksplorasi yang belum diketahui (exploring).

👤 Keunggulan Human QA (Manual)
  • Intuisi & Konteks Bisnis: Memahami ekspektasi user riil & flow rumit yang butuh empati.
  • Exploratory Testing: Menemukan anomali tak terduga di luar test case tertulis.
  • Usability & Visual QA: Mengevaluasi kenyamanan visual, tone bahasa, & UX adaptif.
🤖 Keunggulan Automation QA (Cypress)
  • Kecepatan & Skala Masif: Eksekusi ratusan test case regresi dalam hitungan menit.
  • Eliminasi Human Fatigue: Jalankan Smoke Test identik berulang tanpa resiko lalai/bosan.
  • Fast Feedback CI/CD: Langsung jegal bug sebelum kode sempat masuk ke production.
🤝 Sinergi Ideal: Automation mengambil alih beban repetitif agar QA Engineer punya ruang eksplorasi mendalam pada skenario kompleks.
Prinsip: Automation bukan pengganti QA, melainkan super-power bagi tim QA. Slide 03
Phase 02: Analysis
Persiapan Analisis Bisnis: Rules & Validasi
04
1. RBAC & Matrix Akses

Memetakan kewenangan tiap role pengguna pada halaman aplikasi:

  • Admin: Akses CRUD & tombol approve aktif.
  • Staff/Viewer: Menu terkunci, tombol edit berstatus disabled.
  • Multi-tenant session isolation.
2. Client-Side Rules

Feedback instan pada browser sebelum payload terkirim:

  • Pemeriksaan Regex format email/password.
  • Limit karakter teks & batasan ukuran upload file.
  • Mandatory check (* merah tidak boleh kosong).
3. Server Rules & Edge Cases

Penolakan integritas data oleh API backend:

  • Pencegahan input duplikat nomor unik/NIK.
  • Validasi plafon limit transaksi harian.
  • Boundary value test (input nilai 0, negatif, max limit).
Quality Assurance: Memastikan sistem menolak data salah dengan tepat. Slide 04

Phase 04: Fundamentals
Anatomi Web: Elemen HTML vs Komponen UI
06
Elemen Web (HTML Native Tag)

Elemen atomik bawaan browser yang sederhana dan minim dependensi logika.

  • Contoh: <input>, <button>, <select>, <table>.
  • Struktur statis, interaksi bawaan peramban (*native behavior*).
  • Cypress bisa langsung berinteraksi tanpa jeda animasi khusus.
Komponen Web (Modern Component)

Gabungan tag HTML, CSS styling, dan logic interaktif (React, Vue, dll.).

  • Contoh: Modal Dialog, Datepicker, Custom Select, Drawer.
  • Memiliki State: animasi fade-in, backdrop layer, dan DOM yang baru di-render ketika di-trigger.
  • Membutuhkan auto-waiting agar tidak gagal saat elemen sedang beranimasi.
Memahami struktur komponen mempermudah navigasi elemen yang dinamis. Slide 06
Phase 05: Core Syntax
Cypress Common Commands & Chaining
07
Perintah Fungsi Contoh Pemakaian
cy.visit() Navigasi membuka URL cy.visit('/login')
cy.get() Query mencari elemen di DOM cy.get('[data-cy="input-user"]')
.type() / .click() Action: mengisi form / menekan tombol cy.get('#pass').type('secret123')
.should() Assertion / validasi kondisi visual cy.get('.toast').should('be.visible')
cy.contains() Menemukan elemen berdasarkan teks cy.contains('button', 'Simpan').click()
Pola Command Chaining: Perintah disambung dari kiri ke kanan layaknya kalimat:

Command Cypress berjalan asinkron dan otomatis mengantre. Slide 07
Phase 06: Best Practices
Selector Strategy: Mengapa Harus data-cy?
08
1. Rentan Rusak (Flaky)
cy.get('.btn-primary') cy.contains('Simpan')

CSS Class sering berubah saat tim FE redesign tampilan. Copy teks rentan gagal saat ada fitur multi-bahasa.

2. Cukup Aman (Fallback)
cy.get('input[name="user"]') cy.get('#login-form')

Atribut native form (name, id) cukup stabil, tapi kadang ID digenerate otomatis oleh compiler framework.

3. Paling Resilient
cy.get('[data-cy="btn-login"]') cy.getByCy('submit-form')

Atribut khusus testing. Kebal terhadap pergantian CSS, framework UI, maupun perombakan tata letak komponen.

🤝 Sinergi FE & QA: Minta tim Front-End menyematkan atribut data-cy pada komponen dasar Design System (<Button/>, <Input/>).
Stabilitas automation ditentukan oleh pemilihan selector yang tidak terikat visual. Slide 08

Mekanisme 6 tahap: Cypress di sisi frontend sebagai user traffic recorder, JMeter di CI/CD sebagai lightweight pipeline executor.

Phase 09: Infrastructure
Keunggulan Pendekatan Hybrid di Server CI/CD
11
1. Hemat Compute & RAM

Browser headless Chrome butuh alokasi memori besar (~1.2 GB+ per runner).

JMeter mode non-GUI hanya membutuhkan sekitar ~150 MB RAM, membuat build server jauh lebih hemat dan cepat.

2. Kebal UI Rendering Lag

Menghilangkan false-negative akibat delay font, viewport resolution, atau CSS render lambat di server runner.

Pipeline hanya fokus pada validasi status payload, kode respon HTTP, dan kecepatan balasan server.

3. Siap untuk Load Testing

File .jmx hasil convert bisa langsung di-scale menjadi uji performa/stress test.

Cukup atur jumlah Thread Group (Virtual Users) di JMeter untuk simulasi lonjakan ribuan user serentak.

Optimalisasi resource: Pipeline cepat, biaya server efisien. Slide 11
